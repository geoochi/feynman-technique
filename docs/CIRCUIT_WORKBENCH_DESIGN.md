# 电学工作台（案例 14）设计草案

更新：2026-10-13。状态：**设计草案，未实施**。本文对应 [待开发实验清单](EXPERIMENT_TODO.md) 第 14 项与[长期路线图](ROADMAP.md)阶段五的自由搭建候选，用于满足其“开始条件：完成单独的交互、求解与维护范围设计”。本文不表示已立项或已排期。

## 1. 核心问题与目标

**如何通过连接元件设计并解释一个电路？** 与固定电路案例（11 欧姆定律、12 串联与并联、13 电容充放电）不同，工作台把“电路结构”本身交给学习者：放置元件、连线、读数、排错。教学目标是把“会套公式”变成“能解释自己搭出的回路为什么得到这个电流”。

## 2. 首版范围与非目标

**范围内（首版）**

- 有限规模的**直流电阻网络**：理想电压源、理想电阻、导线与节点。
- 放置、移动、删除元件；在端子之间连线；修改元件数值。
- 每个元件/支路的电压、电流读数；总功率与功率平衡。
- 明确的错误提示：开路、短路、悬空节点、无解（不一致）电路。
- 键盘可操作与真实手机触摸连接交互。

**范围外（首版不做，后续独立评估）**

- 电容、电感等动态元件（需要时域积分与状态恢复，属独立设计）。
- 交流、相量、非线性元件（二极管、灯泡）。
- 任意规模网络、符号求解、电路保存/分享、URL 或服务端存储。

## 3. 与现有案例协议的主要冲突（必须先解决）

当前协议（[案例协议](CONTRIBUTING_DESIGN.md)、`scripts/manifest.schema.json`、`scripts/catalog.ts`）要求：

- `parameters.schema.json`：**只有数值参数**（`type:"number"`，带 min/max/step/unit/三语言 labels）。
- `snapshot.schema.json`：**只有数值状态**（每个字段 `{type:"number", minimum, maximum}`，且 `additionalProperties:false`）。
- 快照接口 `Snapshot.internalState` 为 `Params`（`Record<string, number>`）。

工作台需要**结构化数据**（元件列表与连线），无法用标量参数表达。因此实施 14 之前，必须先扩展协议。两种候选方案：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A · 结构参数 | 新增参数类型 `netlist`（元件/连线数组），扩展 manifest/parameter schema、`ParameterControl` 渲染、快照校验与 `RuntimeLabConfig` | 改动中心 schema 与共享运行时，影响全部案例的校验路径，需要版本升级（schemaVersion 3）与迁移说明 |
| B · 案例自持状态 | 参数仍为数值（仅元件数值），电路结构由案例 `view` 自持，快照扩展为“数值 + 结构” | 需要扩展快照格式与恢复接口；跨会话/语言切换的恢复语义变复杂 |

**建议**：采用 A，并把 `schemaVersion` 从 2 升到 3，仅新增可选类型，不改动既有数值案例。这需要单独的协议变更设计与兼容性验证，是 14 的**前置工作**，不应与首个案例实现混在同一个改动里。

## 4. 数据模型（草案）

```text
Circuit = {
  nodes:     NodeId[]                                  // 拓扑节点
  elements:  Element[]                                 // 元件
  source:    { nodeA, nodeB, emf }                     // 理想电压源
}
Element =
  | { id, kind: "resistor", nodeA, nodeB, resistance } // 欧姆电阻，resistance > 0
  | { id, kind: "wire",     nodeA, nodeB }             // 理想导线（合并节点）
```

- 元件数值走参数系统（电阻 Ω、电动势 V），结构走结构参数。
- 快照需同时保存结构与数值，并在恢复前校验：节点数上限、元件数上限、无重复 id、每个端子都属于已知节点、数值在范围内。

## 5. 求解器（草案）

- 采用**节点电压法（电阻版 MNA）**：把导线合并为同一节点，为每个非参考节点列 KCL 方程，理想电压源作为约束方程加入。
- 规模上限（首版）：≤ 20 个节点、≤ 30 个元件，保证浏览器内实时求解（一次求解应在毫秒级）。
- 数值与退化处理：
  - 电压源被零阻通路短接、或存在孤立子网络 → 矩阵奇异，判定为“不一致/短路”，给出明确提示，**不返回 NaN**。
  - 悬空节点 → 明确标注“未连接”，不参与求解或提示后忽略。
  - 全部为理想元件，不引入“有限内阻兜底”来掩盖错误拓扑。
- 求解器为纯 TS、与 UI 分离，便于独立测试。

## 6. 交互设计（草案）

- **画布**：SVG 网格，元件吸附到网格点；端子为可聚焦的小圆。
- **调色板**：电阻、电压源、导线；点击或拖放放置。
- **连线**：点选两个端子完成连接；重复连接给出提示。
- **选中与编辑**：选中元件后在右侧参数面板改数值或删除；导线可直接删除。
- **键盘**：Tab/Shift+Tab 遍历元件与端子，Enter/空格 选择与确认，方向键在网格上移动，Delete 删除，Esc 取消。
- **手机**：点按端子连线、拖拽放置；命中区域不小于 44×44 CSS px；避免依赖悬停。
- **无障碍**：所有操作有可读名称与可见焦点，状态不能只靠颜色（错误用文字 + 图标）。
- **布局**：沿用现有课程壳（左侧简介与问题、中央画布、右侧控制与读数），不新增七步导航。

## 7. 错误与边界提示

| 情形 | 提示 |
| --- | --- |
| 电压源被短接 / 无解 | 明确“电路不一致：电压源被短路”，不显示读数 |
| 悬空节点 | “存在未连接的节点”，高亮该节点 |
| 缺少回路 | “电路尚未形成闭合回路” |
| 数值越界 | 沿用参数控件既有的范围提示 |

## 8. 验证计划（草案）

- **求解器**：与已知解对照（分压、分流、惠斯通电桥平衡与非平衡）、对称性（交换对称元件读数不变）、功率平衡（Σ 元件功率 = 0）、退化输入（短路/开路/孤立）不产生 NaN。
- **结构校验**：越界节点、重复 id、超限规模被拒绝；快照往返恢复一致。
- **交互**：放置/连线/删除/改值的冒烟；键盘可达；手机视口无横向溢出、可完成一次连线。
- **性能**：上限规模下一次求解耗时记录；不阻塞 UI。

## 9. 维护范围与风险

- 求解器与元件协议属于**长期维护**接口，一旦发布应保持向后兼容；结构参数与快照版本需要迁移策略。
- 自由搭建的交互复杂度和可访问性成本显著高于固定电路案例，需要真实手机与键盘实测，不能只靠桌面模拟。
- 风险：范围膨胀（动态元件、交流、保存分享）。首版必须严格限制在“有限直流电阻网络”，其余另立设计。
