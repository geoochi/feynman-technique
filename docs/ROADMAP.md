# Feynman Technique 长期开发路线图

更新：2026-10-13。状态：发展规划，不是功能完成声明或固定发布日期承诺。当前基线为首期 v0.1.0 加 Next 静态迁移；2026-10-13 的生产发布与实际线上验收见部署记录，历史验收保留当时事实。

## 1. 长期目标与产品定位

让任何人通过可操作的可视化实验理解知识，能够改变参数、验证预测，并用自己的话解释规律。网站逐步发展为开放的实验与讲解库，让学习者、教师和开发者共同贡献案例。

近期先服务有具体数学或科学疑问的自学者、学生与教师，重点验证高中到大学入门层次的内容是否容易上手。目标人群和难度分层随实际反馈调整，不将这个范围设为永久限制。

网站持续保持无需登录即可体验的静态前端形态，计算发生在访客浏览器。原创代码、讲解、文档和图示统一 MIT；第三方依赖、字体与素材保留自身条款。工程与发布边界见 [工作约定](../AGENTS.md)和[架构](ARCHITECTURE.md)。

## 3. 推进原则与优先级

- 每个实验回答一个明确问题，提供能观察、预测、操作和解释的路径。数值正确、教学有效、操作顺畅分别验证。
- 先完善现有案例，再围绕相邻知识点形成系列；案例数量是容量规划，不作为质量或社区贡献的奖励指标。
- 用户反馈、内容发布和开源贡献持续并行。共用工具随着真实重复需求提取，复杂能力有独立设计与验证后再实施。
- 优先级定义：P0 为可靠性与已知阻塞问题，P1 为学习体验、内容和首批社区贡献，P2 为需求成立后的工具与大型工作台。
- 每阶段交付可用、可验证的结果，满足推进条件后调整下一阶段范围。维护者决定选题与投入，路线图不自动启动开发、外部发布、发帖或自动化。

## 4. 阶段一：可靠使用与学习反馈（当前优先）

**目标：** 一批真实用户能独立使用现有实验，并明确指出自己理解了什么。

| 优先级 | 工作 | 交付与验证 |
| --- | --- | --- |
| P0 | 连接现有 Worker 的 GitHub Builds，统一生产发布 | main 的真实更新触发平台构建、对应 commit 上线；验证失败处理与平台回滚，不增加 Actions 或第二通道 |
| P0 | 收集真实手机操作与加载问题 | 记录机型、系统、网络、语言、版本；复核触摸、输入、画布、读数与 WebGL 回退，优先处理阻断问题 |
| P1 | 按专项计划迁移到 Next.js App Router 静态生成 | 代码、本地与正式发布验收已完成，保留 URL、SEO、三语言状态和模型行为；未达性能预算及实体设备继续跟进 |
| P1 | 邀请约 5–10 位自学者、学生或教师试用 | 观察从问题到解释的完整过程，整理可复现的卡点与教学误解；样本量是初轮建议，不是统计显著性承诺 |
| P1 | 复核现有三个实验的教学与科学表述 | 检查单位、近似条件、公式/读数含义、核心答案和三语言一致性，邀请具备相关知识的人审阅 |
| P1 | 整理已有反馈和搜索观测 | 使用 Issue、访谈记录与现有平台报告；记录来源和版本，不把访问量当作学习效果 |

单摆试用可让读者先预测摆长变成四倍时周期如何变化，再操作并解释平方根关系和小角度条件。二次函数与地球实验也围绕各自核心问题安排一次预测与验证。该试用方式先作为研究记录，不恢复已经取消的七步 UI 导航。

**推进条件：** 主要使用阻塞已有修复或明确处理方案；能报告具体学习发现与误解；每个案例的审阅状态真实可追溯。Git 自动发布需要单独完成真实部署验收，不能仅凭配置文件勾选完成。后续内容工作可在这些验证进行时并行推进。

## 5. 阶段二：形成有联系的实验系列

**目标：** 从三个种子案例逐步发展到约 6–10 个扎实案例，让用户能沿知识联系继续探索。

近期候选优先数学与物理，保留现有地球科学主题。下表只是选题池，未代表已立项或承诺实现：

| 候选方向 | 要回答的问题 | 实施时的范围约束 |
| --- | --- | --- |
| 导数与切线（已上线，待反馈） | 某一点的变化率如何从图形与割线变化看出来？ | 限定 f(x)=x²，双侧间隔、h=0 无定义、解析切线与斜率误差；独立教学审阅待完成 |
| 波的叠加 | 两列波如何相互加强或抵消？ | 限定模型、参数和边界，区分图像与物理解释 |
| 透镜成像 | 物体位置改变时，像的位置与性质如何改变？ | 明确光学近似与适用条件，验证特殊和退化情况 |
| 振动与周期 | 单摆和其他周期运动有什么相同与不同？ | 在现有单摆基础上设计独立学习价值，避免重复案例 |
| 日照与纬度延伸 | 当前昼夜模型还能帮助解释哪些日照差异？ | 围绕已有自转/赤纬模型，不把未实现轨道或实时天气写成能力 |

待开发实验的分批清单、首版范围与逐项进展见 [实验待办清单](EXPERIMENT_TODO.md)。该清单同时标明原有候选和新增建议，不将全部选题视为已立项。

每次新增优先完成一份完整案例：独立模型、已知解/边界等证据、可操作视图、七章讲解、三语言、素材来源、合理的默认状态和失败回退。实验与讲解各自提供可静态读取的正文与元信息。

相关案例可通过讲解中的自然链接建立学习联系。搜索词与难度提示根据真实内容整理；新增筛选维度以案例数量和实际查找问题为依据。目录数据增长时测量首页和讲解的下载量，再决定拆分，不先重构全部内容来源。

**推进条件：** 每个新增案例有明确学习目标、可验证模型与上线记录；至少形成一组有教学联系的实验，并获得实际使用反馈。约 6–10 个是建议阶段规模，优质少量案例也可支撑下一步社区工作。

## 6. 阶段三：让外部贡献者完成首个案例

**目标：** 一位未参与核心开发的人能依据文档完成被合并、可体验的学习贡献。

社区入口已经开放，此阶段与前两阶段并行，不等待达到某个访问量或案例数量。

- 将实际反馈整理为范围清晰的 Issue：实验提案、讲解纠错、翻译、预设与小功能。只有确实易入门且有验证方式的任务才标记 good first issue。
- 用首位外部贡献者的经历检验 CONTRIBUTING、案例示例与本地命令，修正文档中必须询问维护者才能继续的隐含步骤。
- 不会编程也可以提案。缺少翻译的实验允许先提交 Issue 或草稿 PR，协作补齐后再通过三语言生产构建与教学验证。
- 保留作者与素材来源，不以社区规模编造学科维护者。按实际贡献逐步落实审阅负责人；治理、行为规范等文件根据实际维护需要建立。
- 维护者本地检查 PR、运行相称验证与 AI 审查，独立教学审阅单独记录；确认目标版本后纳入生产分支。

**推进条件：** 至少一份有明确验证记录的外部贡献完成合并并上线，维护者能说明投稿、协作与审查过程中的阻碍。记录它是完整新案例、翻译还是纠错；不能把小修复写成已经完成外部新案例里程碑。

## 7. 阶段四：降低持续创作与维护成本

**目标：** 在案例与贡献增加后，让创作、审核和发布仍然简单可靠。

以下能力按触发条件逐项评估，不作为一个必须同时实施的“大平台”项目：

| 能力 | 开始条件 | 验收重点 |
| --- | --- | --- |
| 案例脚手架与模板 | 多次投稿出现相同的文件准备错误 | 新作者能生成并运行符合协议的案例，不需要中心路由手工登记 |
| 轻量目录与按语言/页面加载讲解 | 测量确认文字数据影响首包或导航 | 首页下载量改善，三语言搜索、静态正文与 SEO 不退化 |
| 共用绘图/读数工具 | 多个独立案例存在真实重复需求 | 减少重复代码并保持案例自主布局、状态与资源释放 |
| 版本归档与可下载静态包 | 教师或用户确实需要固定教案版本 | 能访问指定发行、追溯模型变化，明确旧快照兼容与勘误规则 |
| 参数或实验状态分享 | 用户反复需要分享可复现探索 | 先设计 URL 或本地文件方案，包含完整历史状态、校验与大小边界；当前界面保持既有约定直至另行批准 |
| Web Worker / WASM | 性能剖析证明计算阻塞或算法瓶颈 | 与纯 TS 基准比较，验证数值正确、交互延迟、失败回退和维护成本 |
| 独立 SDK / CLI | 仓库内契约稳定且外部有明确复用需求 | 真实外部案例验证安装、版本兼容与文档，不把现有共用文件直接包装成成熟 SDK |

此阶段仍使用 Git 作为内容来源、浏览器作为运行环境。能力设计须依据任务另行确认，不默认添加后台、在线编辑器或账户系统。

## 8. 阶段五：更复杂的实验与长期生态

**目标：** 在学习效果、模型验证和贡献维护已形成稳定实践后，支持更复杂但仍清楚可理解的实验。

电学工作台是已有长期候选：允许组合元件、连接电路、观察电压/电流等变化。先用一个有限任务验证需求，再确定元件协议、求解器、连接交互、单位与边界、错误提示、键盘可达性和移动布局。深色仪表盘只是视觉方向，不代表功能已实现。

更广泛的数学、物理、地球科学和其他学科，按有来源、可验证、有学习价值和具备维护能力的提案逐步扩展。教师用活动材料、固定版本教案和外部嵌入需求可随真实应用场景评估。

开放 API、插件、网页内创作及独立内容仓库都需要具体使用者、权限/安全设计和维护预算。只有已确认需求无法由现有静态形态合理满足时才重新讨论架构；收费、账户同步或在线 AI 不属于当前既定路线的前置条件。

**推进条件：** 大型案例有可独立验收的范围、明确负责人与科学依据；原型完成模型和真实设备验证；能说明新增复杂性为学习者带来的实际价值。

## 9. 内容传播、发现与效果观测

传播与开发同步，以一个知识问题和一段可复现操作介绍一个案例。官网链接尽量直达对应实验；开源贡献介绍使用仓库入口。社交帖子和录屏须基于真实模型状态与许可素材，发布需要维护者授权，本路线图不自动安排发帖。

SEO 后续持续检查抓取、索引、真实查询词、静态正文与深链接；依据读者问题完善核心答案、讲解和相关内链。保留三语言对应关系，不为增加页面数批量生成薄内容，不承诺排名、流量或 AI 引用。

指标分开记录：

| 要观察的结果 | 可以收集的证据 | 不能直接推导的结论 |
| --- | --- | --- |
| 学习者理解了什么 | 操作前预测、操作后解释、误解与访谈记录 | 页面打开或停留就等于掌握知识 |
| 使用是否顺畅 | 真实设备卡点、失败率、参数响应与加载测量 | 本机一次测试代表所有地区与手机 |
| 内容能否被发现 | Search Console 查询/索引、平台来源与案例访问 | 提交 sitemap 就会收录或产生增长 |
| 社区能否参与 | 实际提案、投稿过程、被合并与上线的贡献 | Star 或 PR 数量代表教学质量 |
| 发布是否可靠 | commit/构建/部署对应关系、失败与恢复记录 | 本地构建通过代表正式站点已经上线 |

使用现有平台报告、Issue 与简明研究记录，先解释数据再决定是否增加统计能力。实验室基线与真实用户数据分开；桌面 60fps、移动 30fps、参数响应 P95 <100ms 等既有预算尚待实测，不写成完成状态。

## 10. 最近一个迭代的建议与复盘

以下是下一轮建议顺序，可按维护者时间、反馈与贡献调整，不是固定四周排期：

维护者本次提出的 Next.js 重构已有 [专项实施顺序与验收门槛](archive/2026-10-13-nextjs-migration.md)。P0–P4 代码与本地验收完成，P5 经授权完成正式发布及线上验收；未达预算与真实设备检查单独跟进，后续发布继续按授权执行。下列用户试用、教学复核和社区工作继续作为产品方向，不自动扩充到本次框架迁移中。

1. 建立试用记录，邀请真实用户尝试三个案例；核对 Workers Builds 接入所需状态与权限。
2. 修复具体操作/讲解卡点，完成一次真实手机测试和有范围的教学复核；如实施 Git 接入，验收真实自动发布与恢复。
3. 从选题池和反馈选择一个实验，先写学习问题、模型假设与验证方案，再完成三语言案例和上线验收。
4. 整理一项实际适合新贡献者的任务，支持首份提案或草稿 PR，并复盘贡献指南。

每个迭代结束记录：完成的目标、目标 commit 与部署版本、实际检查、用户发现、未核实项、下一步优先级。采用“候选 → 本轮选定 → 实施 → 验证 → 已上线 → 用户反馈”的状态；工程检查通过不自动等于教学审阅完成。

维护 ROADMAP 的当前基线与阶段状态，不把历史部署记录改写成新事实。架构决策同步 ARCHITECTURE，操作命令同步 DEVELOPMENT，线上状态同步 DEPLOYMENT，界面规则同步 VISUAL_SPEC，代理行为约定同步 AGENTS。阶段完成时附实际记录链接，并重新评估后续范围。

## 11. 2026-10-13 内容迭代：导数与切线

本轮由维护者授权从可实施内容开始推进，选定“导数与切线”，承接二次函数形成第一组数学学习联系。案例限定 f(x)=x²，参数为基点 x₀ 与有符号间隔 h，提供割线/切线、三个读数、左右逼近及零间隔说明。无动画时钟，不增加依赖或公共运行时能力。
